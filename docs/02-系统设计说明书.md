## 1. 总体架构

前后端完全分离，浏览器只与两个服务打交道：Nginx（静态资源）与 FastAPI（JSON API）。

```
┌──────────────────────────────────────────────────────────┐
│                      浏览器（SPA）                        │
│   Vue 3 + Vue Router + Pinia + Element Plus + Axios      │
│   构建产物：/dist 下的 HTML + JS + CSS                     │
└───────────────────────────┬──────────────────────────────┘
                            │ HTTP(S)
                            │ 静态资源：GET /
                            │ 接口请求：GET /api/v1/**
                            ▼
┌──────────────────────────────────────────────────────────┐
│                          Nginx                            │
│   location /      → root /var/www/novel-platform/dist     │
│   location /api/  → proxy_pass http://127.0.0.1:8000      │
│   try_files $uri $uri/ /index.html   ← SPA 路由回退        │
└───────────────────────────┬──────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────┐
│                    FastAPI (Uvicorn)                      │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 路由层  api/v1/*.py                                 │  │
│  │  参数校验(Pydantic) → 鉴权(Depends) → 调 service     │  │
│  └───────────────────────┬────────────────────────────┘  │
│  ┌───────────────────────▼────────────────────────────┐  │
│  │ 业务层  services/*.py                               │  │
│  │  业务规则、事务编排、冗余字段回写                        │  │
│  └───────────────────────┬────────────────────────────┘  │
│  ┌───────────────────────▼────────────────────────────┐  │
│  │ 数据层  models/*.py (SQLAlchemy 2.0 ORM)            │  │
│  └───────────────────────┬────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 横切  core/{config,logger,security,exceptions}      │  │
│  └────────────────────────────────────────────────────┘  │
└───────────────────────────┬──────────────────────────────┘
                            │ PyMySQL（同步连接池）
                            ▼
┌──────────────────────────────────────────────────────────┐
│                    MySQL 8.0 (InnoDB)                     │
│                    novel_platform / utf8mb4               │
└──────────────────────────────────────────────────────────┘
```

## 2. 技术选型

### 2.1 后端

| 技术 | 建议版本 | 选型理由 |
|---|---|---|
| Python | 3.11 ~ 3.13（3.14 亦可） | 生态成熟；3.14 较新，若个别依赖缺 wheel 可回退 3.12 |
| FastAPI | ≥ 0.110 | 自动生成 OpenAPI 文档（答辩演示加分）、Pydantic 强校验、`Depends` 依赖注入清晰 |
| SQLAlchemy | 2.0.x | 2.0 风格 `select()` + 类型注解，比 1.x 更现代；`Mapped[]` 让模型即文档 |
| PyMySQL | 1.1.x | **纯 Python，Windows 免编译**；`mysqlclient` 需要 C 编译环境，容易卡住 |
| Pydantic | 2.x | 请求/响应双模型，字段约束写在声明处 |
| Uvicorn | ≥ 0.27 | ASGI 服务器，`--reload` 开发体验好 |
| PyJWT | 2.x | 只做 JWT 编解码，比 `python-jose` 依赖更少 |
| Loguru | 0.7.x | 一行配置搞定轮转、彩色、异常堆栈 |
| pydantic-settings | 2.x | `.env` 读取与类型校验合一 |

> **为什么不用异步（async/await）**：
> 本项目是典型的「读多写少、数据量小」场景，瓶颈在磁盘 IO 而不在并发连接数。同步代码 + 连接池在毕设规模下性能完全够用，且**代码量减少约 30%、调试栈更直观、答辩更容易讲清**。
> 若要做成论文亮点，可在 P4 阶段挑选 2~3 个高频接口（书籍列表、章节正文）做异步改造，用 `ab` / `wrk` 对比 QPS，形成「性能优化」实验章节。**不要一开始就全异步**。

### 2.2 前端

| 技术 | 建议版本 | 选型理由 |
|---|---|---|
| Vue | 3.4+ | 组合式 API，生态最大，资料最多 |
| Vite | 5+ | 启动秒级，配置简单 |
| Vue Router | 4.x | 官方路由，支持路由守卫做权限 |
| Pinia | 2.x | 比 Vuex 简洁，天然支持组合式 |
| Element Plus | 2.x | 后台管理与表单组件开箱即用 |
| Axios | 1.x | 拦截器统一处理 Token 与错误 |

> **为什么不用 Nuxt / SSR**：小说平台没有 SEO 强需求（毕设演示场景），SSR 会引入 Node 服务端与双端渲染调试成本，收益与代价不匹配。

### 2.3 开发与部署

| 工具 | 用途 |
|---|---|
| Git + GitHub/Gitee | 版本管理，答辩时可展示提交历史 |
| Nginx | 静态托管 + 反向代理 |
| PyCharm / VS Code | 开发 |
| Apifox / Postman | 接口调试（可直接导入 `/docs` 的 OpenAPI） |

### 3.2 三层职责（硬性约束）

| 层 | 可以做什么 | **禁止**做什么 |
|---|---|---|
| `api/`（路由） | 解析参数、调 `Depends` 鉴权、调 service、包装 `ok()` | 写 SQL、写业务分支、直接操作 `db` 之外的复杂逻辑 |
| `services/`（业务） | 业务规则、事务、多次查询编排、冗余字段回写 | 读 `Request` / 返回 `JSONResponse` / 依赖 HTTP 状态码 |
| `models/`（数据） | 表结构、关系、简单 property | 发起查询、依赖 FastAPI |

> 这条约束的价值：service 层可以**脱离 HTTP 单独测试**。论文「系统测试」章节可以展示 service 的单元测试，这是加分项。

### 3.3 一次请求的调用链（以书籍列表为例）

```
GET /api/v1/books?category_id=2&sort=click&page=1
  → books.py:list_books(query: BookQuery, db: Session)
  → book_service.list_books(db, query)
        ├─ 组装 select(Book).where(...)
        ├─ pagination.paginate(db, stmt, page, size)   # 先 count 再 limit
        └─ 返回 (rows, total)
  → schemas.book.BookCard.model_validate(row, from_attributes=True)
  → return ok(PageResult(...))
```

## 4. 关键设计

### 4.1 统一响应与异常

```python
# app/core/response.py
def ok(data=None, message="ok"):
    return {"code": 0, "message": message, "data": data,
            "trace_id": current_trace_id.get()}

def fail(code: int, message: str):
    return JSONResponse(status_code=HTTP_STATUS[code],
                        content={"code": code, "message": message,
                                 "data": None, "trace_id": current_trace_id.get()})
```

异常处理三段式：

| 异常类型 | 处理 |
|---|---|
| `BizError(code, message)` | 业务主动抛出 → `fail(code, message)` |
| `RequestValidationError` | 参数校验失败 → `1001`，`message` 取第一条错误 |
| `Exception` | 兜底 → 记 ERROR 日志（含堆栈）→ `9999`，**不向前端暴露堆栈** |

### 4.2 认证与鉴权

```
登录 → security.create_token(user)
        payload = {"sub": str(user.id), "role": user.role, "exp": now+2h}
        token   = jwt.encode(payload, SECRET_KEY, "HS256")

请求 → deps.get_current_user(authorization: str = Header(...))
        ├─ 缺失/格式错      → BizError(1002)
        ├─ jwt.decode 失败  → BizError(1002)
        ├─ 查库用户不存在     → BizError(1002)
        └─ user.status == 0 → BizError(2003)

角色 → deps.require_role("admin")
        └─ 不匹配 → BizError(1003)
```

**为什么把 `role` 放进 Token**：省一次查库。但**权限判定仍以数据库为准**（`get_current_user` 会查库），避免「管理员被降级后 Token 仍有效」的越权风险。

### 4.3 榜单实现

| 榜单 | 数据来源 | 是否需要新表 |
|---|---|---|
| 点击榜 | `book.click_count` | 否 |
| 收藏榜 | `book.collect_count` | 否 |
| 推荐榜 | `book.recommend_count` | 否（P3 由 `book_vote` 聚合回写） |
| 新书榜 | `created_at` 近 90 天 + `click_count` | 否 |

全部走**冗余计数字段 + 索引排序**，不实时聚合 `COUNT(*)`。这是「空间换时间」的典型应用。

### 4.4 计数器并发安全

```python
# 正确：数据库原子自增
db.execute(update(Book).where(Book.id == bid).values(click_count=Book.click_count + 1))

# 错误：先查后改，并发下会丢更新
book = db.get(Book, bid); book.click_count += 1
```

详情页每次访问都 `+1`，高频写会带来行锁竞争。毕设量级无压力；论文中可注明「生产环境应改为 Redis 计数 + 定时落库」。

### 4.5 正文渲染与 XSS 防护

- 数据库存**纯文本**，段落用 `\n` 分隔。
- 前端渲染：

```vue
<p v-for="(para, i) in paragraphs" :key="i">{{ para }}</p>

<script setup>
const paragraphs = computed(() =>
  chapter.content.split(/\n+/).map(s => s.trim()).filter(Boolean)
)
</script>
```

- 使用 `{{ }}` 插值（自动转义），**严禁 `v-html`**。
- 后端在 Pydantic 层限制 `content` 长度（单章 ≤ 50,000 字）。

### 4.6 分页实现

```python
def paginate(db, stmt, page: int, size: int):
    total = db.scalar(select(func.count()).select_from(stmt.subquery()))
    rows  = db.scalars(stmt.offset((page-1)*size).limit(size)).all()
    return rows, total
```

- 深分页（`OFFSET` 很大）在万级数据下无问题；论文可提及「游标分页」作为优化方向。
- 前端组件统一用 Element Plus `el-pagination`，参数与后端 `page/size` 对齐。

### 4.7 静态资源

| 资源 | 方案 |
|---|---|
| 书籍封面 | 后台上传 → `backend/static/covers/{book_id}.jpg`；开发期也可直接填外链 URL |
| 用户头像 | P3 再做上传，P1 用默认头像 + 外链 |
| 前端构建产物 | Nginx 托管 `dist/` |

> 毕设阶段**不建议**接对象存储（OSS），多一套密钥与网络依赖，答辩时断网就演示失败。

## 5. 核心时序

### 5.1 登录

```
浏览器            FastAPI              MySQL
  │  POST /auth/login │                    │
  ├──────────────────►│                    │
  │                   ├─ SELECT user ─────►│
  │                   │◄──── row ──────────┤
  │                   ├─ verify_password   │
  │                   ├─ UPDATE last_login ►│
  │                   ├─ create_token      │
  │◄── {token,user} ──┤                    │
  ├─ localStorage.set │                    │
  └─ router.push('/') │                    │
```

### 5.2 阅读章节（含进度上报）

```
阅读页               FastAPI                  MySQL
  │ GET /chapters/101  │                        │
  ├───────────────────►│                        │
  │                    ├─ SELECT chapter ──────►│
  │                    ├─ SELECT prev/next id ─►│
  │◄── ChapterDetail ──┤                        │
  ├─ 渲染正文          │                        │
  ├─ 应用本地阅读设置   │                        │
  │                    │                        │
  ├─ (3s 后) POST /history {book,chapter,45%}   │
  ├───────────────────►│                        │
  │                    ├─ INSERT ... ON DUP ───►│
  │◄── {updated:true} ─┤                        │
  └─ 翻页 → 重复上述     │                        │
```

### 5.3 作者发布章节（事务 + 冗余回写）

```
作者后台             FastAPI                         MySQL
  │ POST /author/books/1/chapters                    │
  ├──────────────────►│                               │
  │                   ├─ BEGIN                     ─►│
  │                   ├─ MAX(chapter_no)+1         ─►│
  │                   ├─ INSERT book_chapter       ─►│
  │                   ├─ UPDATE book SET           ─►│
  │                   │    chapter_count+1,          │
  │                   │    word_count+=n,            │
  │                   │    last_chapter_*=...        │
  │                   ├─ COMMIT                    ─►│
  │◄── {chapter_id} ──┤                               │
  └─ 前台立即可见                                     │
```

> 任一步失败整体回滚，保证 `book` 的冗余字段与 `book_chapter` 始终一致。

## 6. 部署架构

### 6.1 开发环境

| 服务 | 端口 | 启动方式 |
|---|---|---|
| 前端 Vite DevServer | 5173 | `npm run dev` |
| 后端 Uvicorn | 8000 | `uvicorn main:app --reload` |
| MySQL | 3306 | Windows 服务 `MySQL80` |

前端 `vite.config.js` 中配置代理，避免开发期跨域：

```js
server: {
  proxy: { '/api': { target: 'http://127.0.0.1:8000', changeOrigin: true } }
}
```

### 6.2 生产环境（单机）

```
                    ┌─────────────┐
   Internet ───────►│    Nginx    │ :80
                    └──────┬──────┘
             ┌─────────────┴──────────────┐
             ▼                            ▼
      /var/www/novel-platform/dist        proxy → 127.0.0.1:8000
      （Vue 构建产物）                     │
                                    ┌─────▼─────┐
                                    │  Uvicorn  │ 1~2 worker
                                    └─────┬─────┘
                                          ▼
                                    ┌───────────┐
                                    │  MySQL    │
                                    └───────────┘
```

**Nginx 关键配置**

```nginx
server {
    listen 80;
    server_name _;
    root /var/www/novel-platform/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /static/ {
        alias /var/www/novel-platform/backend/static/;
    }

    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退，缺了这行刷新 404
    }
}
```

> `try_files` 那一行是前后端分离部署最常踩的坑：直接访问 `/book/1` 会 404，因为 Nginx 找不到该物理文件。

## 7. 设计决策记录（ADR）

> 答辩时最容易被追问「为什么这样选」，这里先备好答案。

| 编号 | 决策 | 备选方案 | 理由 | 代价 |
|---|---|---|---|---|
| ADR-01 | 同步 SQLAlchemy | 全异步 | 代码量少 30%，调试直观，毕设数据量无需异步 | 高并发下吞吐不及异步（本项目不涉及） |
| ADR-02 | PyMySQL | mysqlclient | 纯 Python，Windows 免编译 | 性能略低（可忽略） |
| ADR-03 | JWT 无状态 | Session + Redis | 无需额外中间件，天然支持前后端分离 | 无法主动踢人下线（用 `status` 字段兜底） |
| ADR-04 | 单级分类 + 标签 | 多级分类树 | 少写一套树形 CRUD 与递归查询 | 导航精细度不如商业站 |
| ADR-05 | 评论先发后审 | 先审后发 | 无敏感词库时，先审会让演示流程卡顿 | 有违规内容风险（毕设环境可控） |
| ADR-06 | 正文纯文本 | 富文本 HTML | 防 XSS、省存储、字数统计简单 | 无排版能力（小说不需要） |
| ADR-07 | 冗余统计字段 | 每次实时聚合 | 列表页性能，且可建索引排序 | 需保证回写一致性（用事务约束） |
| ADR-08 | 阅读进度单行 Upsert | 阅读流水表 | 查询 O(1)，不会无限膨胀 | 丢失历史足迹 |
| ADR-09 | Element Plus | 自研组件库 | 后台管理开发速度提升数倍 | 前台风格偏「管理系统」，需自写样式覆盖 |
| ADR-10 | 不接对象存储 | 本地静态目录 | 无外部依赖，断网可演示 | 部署迁移时需手动搬文件 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Python 3.14 部分依赖无 wheel | 装不上 | 优先用纯 Python 包；实在不行装 3.12 并行环境 |
| 前端页面多，样式工作量超预期 | 拖期 | 先用 Element Plus 默认样式跑通功能，P4 再统一美化 |
| 章节正文数据量大导致目录接口变慢 | 体验差 | 目录与正文强制拆分接口（已写入 API-11/13） |
| 演示环境断网 | 答辩事故 | 全部依赖本地化：图片本地、字体本地、`npm run build` 产物随包 |
