## 1. 通用约定

| 项 | 约定 |
|---|---|
| 基础路径 | `http://localhost:8000/api/v1` |
| 数据格式 | 请求/响应均为 `application/json; charset=utf-8` |
| 字段命名 | `snake_case`（与数据库一致，减少前后端映射心智负担） |
| 时间格式 | 字符串 `YYYY-MM-DD HH:mm:ss`，如 `2026-11-26 11:20:00` |
| ID 类型 | JSON number（BIGINT，实际值远小于 2^53，无精度风险） |
| 空值 | 统一用 `null`，不用空字符串表示「没有」 |
| 布尔 | `true` / `false`（**不**用 0/1） |
| 状态码 | 值域见「6. 枚举字典」，前端自带映射表转中文 |
| 分页 | 见「5. 分页约定」 |
| 跨域 | 开发环境后端开启 CORS，允许 `http://localhost:5173` |
| 接口文档 | 后端运行时自动生成 Swagger：`http://localhost:8000/docs` |

## 2. 认证与鉴权

### 2.1 令牌传递

登录成功后返回 JWT，后续请求在 Header 中携带：

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 2.2 令牌内容（Payload）

```json
{
  "sub": "6",
  "role": "reader",
  "iat": 1774586400,
  "exp": 1774593600
}
```

- `sub`：用户 ID（字符串）
- `role`：角色，用于服务端快速鉴权
- 有效期 **7200 秒（2 小时）**

### 2.3 三种鉴权级别

| 标记 | 含义 | 未满足时 |
|---|---|---|
| 🔓 公开 | 无需登录 | — |
| 🔐 登录 | 需要有效 Token | `401` + `code=1002` |
| 👑 角色 | 需要指定角色（author / admin） | `403` + `code=1003` |

> **「可选登录」**：部分公开接口（如书籍详情）在携带 Token 时会额外返回 `is_collected` 等个性化字段；不携带也不报错。

### 2.4 鉴权失败的前端处理约定

| code | 前端行为 |
|---|---|
| `1002` | 清除本地 Token → 跳转 `/login?redirect=<当前路径>` |
| `1003` | 提示「没有权限」并留在当前页 |
| 其他 | 弹出 toast，展示 `message` |

## 3. 统一响应格式

**所有接口**（含错误）响应体结构固定：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "3f8a1c2e"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功，非 0 为业务错误码 |
| `message` | string | 给用户看的提示，可直接展示 |
| `data` | any | 业务数据；错误时为 `null` |
| `trace_id` | string | 请求追踪 ID，排查问题时报给后端 |

**HTTP 状态码使用规则**：业务错误也返回对应 HTTP 状态码（便于前端拦截器统一处理），但**响应体结构不变**。

| 场景 | HTTP | code |
|---|---|---|
| 成功 | 200 | 0 |
| 参数校验失败 | 422 | 1001 |
| 未登录 | 401 | 1002 |
| 无权限 | 403 | 1003 |
| 资源不存在 | 404 | 1004 |
| 业务规则拒绝 | 400 | 2xxx / 3xxx / 4xxx / 5xxx |
| 服务器异常 | 500 | 9999 |

## 4. 错误码表

| code | message | HTTP | 触发场景 |
|---|---|---|---|
| `0` | ok | 200 | 成功 |
| `1001` | 参数校验失败 | 422 | 字段缺失、格式错误、长度越界 |
| `1002` | 登录已失效，请重新登录 | 401 | Token 缺失/过期/非法 |
| `1003` | 没有操作权限 | 403 | 角色不足、操作他人资源 |
| `1004` | 资源不存在 | 404 | 书籍/章节/评论不存在 |
| `1005` | 操作过于频繁，请稍后再试 | 429 | 登录或评论频率超限 |
| `2001` | 用户名已被占用 | 400 | 注册重名 |
| `2002` | 用户名或密码错误 | 400 | 登录失败（不区分哪个错） |
| `2003` | 账号已被禁用 | 403 | `status = 0` |
| `2004` | 原密码不正确 | 400 | 修改密码 |
| `3001` | 书籍不存在或已下架 | 404 | 书已下架 / ID 不存在 |
| `3002` | 章节不存在 | 404 | 章节被删 |
| `3003` | 章节号已存在 | 400 | 作者手动指定了重复章节号 |
| `4001` | 该书籍已在书架中 | 400 | 重复收藏（前端应做幂等兜底） |
| `5001` | 评论内容不合法 | 400 | 空白 / 超长 |
| `5002` | 只能删除自己的评论 | 403 | — |
| `6001` | 只能管理自己的作品 | 403 | 作者越权 |
| `9001` | 数据库操作失败 | 500 | 事务异常 |
| `9999` | 服务器内部错误 | 500 | 未捕获异常 |

## 5. 公共数据结构（DTO）

> 前端应按这几个结构定义 TypeScript 类型 / JSDoc 注释，避免字段猜错。

### 5.1 `UserBrief`

```json
{ "id": 6, "username": "reader1", "nickname": "一个读者", "avatar": "", "role": "reader" }
```

### 5.2 `CategoryBrief`

```json
{ "id": 2, "name": "武侠仙侠" }
```

### 5.3 `BookCard`（列表卡片，轻量）

```json
{
  "id": 1,
  "title": "山河剑歌",
  "cover": "/static/covers/1.jpg",
  "author": { "id": 2, "username": "author1", "nickname": "青衫客" },
  "category": { "id": 2, "name": "武侠仙侠" },
  "status": 0,
  "word_count": 42310,
  "chapter_count": 42,
  "last_chapter_title": "第42章　剑指苍穹",
  "last_update_at": "2026-11-25 20:00:00",
  "click_count": 58210
}
```

### 5.4 `BookDetail`（详情，含正文外的全部信息）

在 `BookCard` 基础上追加：

```json
{
  "last_chapter_id": 42,
  "intro": "少年提剑下山，本只想讨一口饭吃……",
  "tags": ["热血", "升级流"],
  "score": 9.2,
  "collect_count": 3120,
  "recommend_count": 0,
  "is_recommend": true,
  "created_at": "2026-11-01 09:00:00",
  "is_collected": false
}
```

### 5.5 `ChapterBrief`（目录项）

```json
{ "id": 101, "chapter_no": 3, "title": "第3章　故人", "word_count": 820, "created_at": "2026-11-23 20:00:00" }
```

### 5.6 `ChapterDetail`（正文）

```json
{
  "id": 101,
  "book_id": 1,
  "book_title": "山河剑歌",
  "chapter_no": 3,
  "title": "第3章　故人",
  "content": "　　天色尚未亮透……\n\n　　这是故事推进到第 3 段的时候。",
  "word_count": 820,
  "prev_id": 100,
  "next_id": 102,
  "is_collected": true
}
```

> `content` 是**纯文本**，段落用 `\n\n` 分隔。前端必须按行 `split` 后渲染 `<p>`，**禁止 `v-html`**。

> `prev_id` / `next_id` 指向**相邻的 `status=1`（未屏蔽）章节**；已是首章/末章时对应字段为 `null`。查询时跳过 `status=0` 的屏蔽章节。

### 5.7 `CommentItem`

```json
{
  "id": 12,
  "user": { "id": 6, "username": "reader1", "nickname": "一个读者", "avatar": "", "role": "reader" },
  "content": "开头那段写得很稳，没有急着抛设定。",
  "like_count": 12,
  "created_at": "2026-11-24 21:10:00",
  "parent_id": null,
  "replies": [
    {
      "id": 13,
      "user": { "id": 5, "username": "reader2", "nickname": "夜读人", "avatar": "", "role": "reader" },
      "content": "同感，前两章几乎没提金手指。",
      "like_count": 2,
      "created_at": "2026-11-24 22:02:00",
      "parent_id": 12,
      "replies": []
    }
  ]
}
```

> 只支持**两层**：主楼 + `replies`。`replies` 内的 `replies` 恒为空数组，前端不应再递归。

### 5.8 `PageResult<T>`

```json
{ "list": [], "total": 128, "page": 1, "size": 20, "pages": 7 }
```

| 字段 | 说明 |
|---|---|
| `list` | 当前页数据 |
| `total` | 总条数 |
| `page` | 当前页码（从 1 开始） |
| `size` | 每页条数 |
| `pages` | 总页数 = `ceil(total / size)` |

### 5.9 分页约定

| 参数 | 类型 | 默认 | 范围 | 说明 |
|---|---|---|---|---|
| `page` | int | 1 | ≥ 1 | 页码，从 1 开始 |
| `size` | int | 20 | 1~50 | 每页条数，超范围自动截断 |

- 页码超出总页数时返回**空列表**，`code = 0`（不报错）。
- 目录接口 `size` 上限放宽到 **500**。

## 8. 接口详情

### 8.1 认证与用户

---

#### API-01　POST `/auth/register`

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|:--:|---|---|
| `username` | string | 是 | 3~20 字符，字母/数字/下划线 | 登录名 |
| `password` | string | 是 | 6~32 字符 | 明文密码（HTTPS 传输） |
| `password_confirm` | string | 是 | 同上 | 二次确认，服务端也比对 |
| `email` | string | 否 | 合法邮箱，≤ 128 | — |
| `nickname` | string | 否 | ≤ 20 | 不填则用 `username` |

```json
{ "username": "newreader", "password": "abc123456", "password_confirm": "abc123456", "email": "a@b.com" }
```

**响应**（注册即登录）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200,
    "user": { "id": 7, "username": "newreader", "nickname": "newreader", "avatar": "", "role": "reader" }
  },
  "trace_id": "a1b2c3d4"
}
```

**错误**：`2001` 用户名已占用；`1001` 参数非法

---

#### API-02　POST `/auth/login`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|:--:|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

**响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200,
    "user": { "id": 1, "username": "admin", "nickname": "站务组", "avatar": "", "role": "admin" }
  },
  "trace_id": "e5f6g7h8"
}
```

**错误**：`2002` 用户名或密码错误；`2003` 账号禁用；`1005` 频率超限

> 服务端在登录成功时更新 `last_login_at`，并写一条业务日志（不含密码）。
> 前端根据 `user.role` 决定是否展示「作者中心 / 管理后台」入口。

|---|---|---|
| `nickname` | string | 1~20 |
| `avatar` | string | ≤ 255，URL 或相对路径 |

**响应**：同 API-03。

---

#### API-05　PUT `/auth/password`　🔐

| 字段 | 类型 | 必填 | 说明 |
|---|---|:--:|---|
| `old_password` | string | 是 | 原密码 |
| `new_password` | string | 是 | 6~32，且不等于原密码 |

**响应**：`data` 为 `null`。修改成功后前端应强制重新登录。

**错误**：`2004` 原密码不正确

#### API-06　POST `/auth/logout`　🔐

无请求体。返回 `data: null`。

> JWT 无状态，服务端不维护会话；此接口仅用于写审计日志，前端负责清除本地 Token。

### 8.2 首页与书库

#### API-07　GET `/home`

一次返回首页所需全部数据，**避免前端串行请求**。

**响应 `data`**

```json
{
  "banners": [ { "id": 1, "title": "山河剑歌", "cover": "/static/covers/1.jpg", "intro": "少年提剑下山……" } ],
  "categories": [ { "id": 1, "name": "玄幻奇幻", "book_count": 2 } ],
  "ranks": {
    "click": [ /* BookCard × 10 */ ],
    "collect": [ /* BookCard × 10 */ ],
    "recommend": [ /* BookCard × 10 */ ],
    "new": [ /* BookCard × 10 */ ]
  },
  "latest": [ /* BookCard × 12，按 last_update_at 倒序 */ ],
  "recommend": [ /* BookCard × 6，is_recommend = 1 */ ]
}
```

> 四个榜单在服务端并行查询后组装；若某榜单为空返回 `[]`，前端展示「暂无数据」占位。

#### API-09　GET `/books`

书库列表 / 筛选 / 搜索三合一。

**Query 参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|:--:|---|---|
| `category_id` | int | 否 | — | 分类筛选 |
| `keyword` | string | 否 | — | 匹配书名或作者昵称（`LIKE`） |
| `status` | int | 否 | — | `0` 连载 / `1` 完结 |
| `sort` | string | 否 | `update` | `update` / `click` / `new` / `word` |
| `page` | int | 否 | 1 | — |
| `size` | int | 否 | 20 | ≤ 50 |

**响应**

```json
{
  "code": 0, "message": "ok",
  "data": {
    "list": [ /* BookCard */ ],
    "total": 12, "page": 1, "size": 20, "pages": 1
  },
  "trace_id": "xxxx"
}
```

**排序实现对照**

| `sort` | ORDER BY | 命中索引 |
|---|---|---|
| `update` | `last_update_at DESC` | `idx_update` |
| `click` | `click_count DESC` | `idx_click` |
| `new` | `created_at DESC` | 主键附近，数据量小可接受 |
| `word` | `word_count DESC` | 全表排序（书量小无压力，论文可注明） |

> `keyword` 存在时，`sort` 默认降级为 `click`（相关性差，热度兜底）。

#### API-10　GET `/books/{book_id}`　🔓 可选登录

**响应 `data`**：`BookDetail`（见 5.4）。

未登录时 `is_collected` 恒为 `false`。

**错误**：`3001` 书籍不存在或已下架

> 副作用：`click_count + 1`。实现上用 `UPDATE book SET click_count = click_count + 1 WHERE id = ?`，**不使用**「先查后改」，避免并发丢失更新。

### 8.4 评论

#### API-22　POST `/comments`　🔐

| 字段 | 类型 | 必填 | 说明 |
|---|---|:--:|---|
| `book_id` | int | 是 | — |
| `chapter_id` | int | 否 | 传则为章评，不传为书评 |
| `parent_id` | int | 否 | 传则为回复，只能回复主楼（`parent_id` 为 null 的评论） |
| `content` | string | 是 | 1~500 字，去除首尾空白后非空 |

#### API-23　DELETE `/comments/{comment_id}`　🔐

逻辑删除：`status = 2`。仅评论作者本人或管理员可操作。

> 若删除的是主楼（`parent_id IS NULL`），其下所有回复在同一事务内一并置为 `status = 2`，避免出现「孤儿回复」。

**错误**：`5002` 非本人评论

#### API-41　POST `/upload`　🔐

上传图片（封面 / 头像），`multipart/form-data`。

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|:--:|---|---|
| `file` | file | 是 | jpg/png/webp，≤ 2MB | 图片文件 |
| `scene` | string | 否 | `cover` / `avatar`，默认 `cover` | 用途，决定存放子目录 |

**响应**

```json
{ "code": 0, "message": "ok", "data": { "url": "/static/covers/1.jpg" }, "trace_id": "xxxx" }
```

**规则**

- 文件名由服务端生成 `{scene}/{yyyymmdd}/{uuid}.{ext}`，**不信任客户端文件名**（防路径穿越）。
- 校验真实文件头（MIME），不只信扩展名；超大小返回 `1001`。
- P1 过渡方案：后台建书时 `cover` 也可直接填外链 URL，不上传也能跑通。

## 9. 前端对接约定

### 9.1 Axios 封装要点

```js
// src/api/request.js 伪代码
const service = axios.create({ baseURL: '/api/v1', timeout: 10000 })

service.interceptors.request.use(cfg => {
  const token = localStorage.getItem('novel_platform_token')
  if (token) cfg.headers.Authorization = `Bearer ${token}`
  return cfg
})

service.interceptors.response.use(
  res => {
    const { code, message, data } = res.data
    if (code === 0) return data          // 业务层直接拿 data
    ElMessage.error(message)
    return Promise.reject(new Error(message))
  },
  err => {
    const code = err.response?.data?.code
    if (code === 1002) { /* 清 token，跳登录 */ }
    ElMessage.error(err.response?.data?.message || '网络异常')
    return Promise.reject(err)
  }
)
```

### 9.2 约定清单

| 约定 | 说明 |
|---|---|
| 返回解包 | 拦截器统一返回 `data`，页面里不再写 `res.data.data` |
| Token 存储 | `localStorage`，键名 `novel_platform_token` |
| 用户信息 | Pinia `userStore`，刷新页面时调 `GET /auth/me` 恢复 |
| 401 处理 | 清 Token → `router.push('/login?redirect=' + encodeURIComponent(route.fullPath))` |
| 图片地址 | `cover` 可能是相对路径，前端用 `new URL(cover, import.meta.env.VITE_API_ORIGIN)` 拼接 |
| 时间展示 | 列表统一显示 `MM-DD HH:mm`，详情页显示完整时间 |

### 9.3 后端实现要点（给未来的自己）

- 统一响应由 `app/core/response.py` 的 `ok()` / `fail()` 生成，**禁止各路由手写 dict**。
- 全局异常处理器拦截 `RequestValidationError` → `1001`，`HTTPException` → 对应 code，`Exception` → `9999`。
- 每个请求生成 `trace_id`，写入响应体与响应头 `X-Trace-Id`，并注入日志上下文。
- 分页统一走 `app/utils/pagination.py`，避免每个接口重复写 `offset/limit`。
