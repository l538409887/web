# 源码阅读路线

> 给「第一次读这个项目」的人（包括几个月后的自己）准备的地图。
> 按本文顺序读，大约 **3 小时**能摸清全部主流程；只想快速上手，读第 3 节即可。

## 1. 先把环境准备好

### 1.1 用什么打开

| 部分 | 推荐工具 | 原因 |
|---|---|---|
| 后端 `backend/` | **PyCharm**（`E:\JetBrainsIDE\PyCharm\bin\pycharm64.exe`） | Python 跳转定义、断点调试最顺 |
| 前端 `frontend/` | **VS Code**（`code "E:\基于python的轻量化web小说平台\毕设内容"`） | 单文件组件与样式高亮更好 |

也可以整个项目都用 VS Code 打开（需要装 `Python` + `Vue - Official` 两个扩展）。

### 1.2 PyCharm 必须设解释器

`File → Settings → Project → Python Interpreter → Add → Existing`，选：

```
E:\基于python的轻量化web小说平台\毕设内容\backend\.venv\Scripts\python.exe
```

不设的话 `import app.xxx` 会全红、无法跳转。

### 1.3 排除大目录（否则 IDE 会卡）

右键 → `Mark Directory as → Excluded`：

- `frontend/node_modules`
- `backend/.venv`
- `frontend/dist`

### 1.4 让服务跑起来（边读边看效果）

```powershell

cd "E:\基于python的轻量化web小说平台\毕设内容\backend"

# 终端 2
```

- 页面：<http://localhost:5173>

## 2. 代码地图

### 2.1 后端规模

| 目录 | 文件 | 行数 | 职责 |
|---|---:|---:|---|
| `backend/app/api/v1/` | 18 | 1967 | 路由层：接参数、调 service、包响应 |
| `backend/app/services/` | 15 | 3407 | **业务逻辑都在这里** |
| `backend/app/models/` | 14 | 495 | 表结构（SQLAlchemy）|
| `backend/app/schemas/` | 10 | 390 | 入参校验 / 出参格式化（Pydantic）|
| `backend/app/core/` | 11 | 735 | 配置、鉴权、限流、水印、日志 |
| 合计 | 72 | 7031 | |

18 个路由模块：
`auth / home / books / chapters / categories / comments / shelf / wallet / interaction / reports / rank / authors / author / user / notices / admin / upload`

`auth / book / chapter / comment / shelf / wallet / interaction / report / author / admin / home / notice / stat / moderation`

> 榜单没有单独的 service——它和书库列表共用 `book_service` 的排序逻辑，
> 周/月榜的聚合在 `stat_service`。

### 2.2 前端规模

| 目录 | 文件 | 行数 | 职责 |
|---|---:|---:|---|
| `frontend/src/views/` | 24 | 8310 | 页面（一个页面一个 `.vue`）|
| `frontend/src/components/` | 17 | 3624 | 可复用组件 |
| `frontend/src/api/` | 5 | 199 | 接口封装（`index.js` 汇总 + `admin/author/wallet` 分端）|
| `frontend/src/stores/` | 3 | 148 | Pinia 全局状态 |
| `frontend/src/router/` | 1 | 186 | 路由表 + 守卫 |
| `frontend/src/layouts/` | 2 | 284 | 三种布局 |

### 2.3 一句话记住分层

> **路由层不写业务，service 层不碰 Request/Response。**

路由里只有：取参数 → 调 service → `ok(...)` 返回。
所有判断（能不能买、能不能看、有没有权限）都在 service。

## 3. 后端阅读路线（2 小时）

### 阶段 A：先看骨架（15 分钟）

**① `backend/main.py`（84 行）**

重点看两个中间件的**注册顺序**：

| 行 | 内容 | 为什么重要 |
|---|---|---|
| 42 | `limit_middleware` | 限流 |
| 50 | `trace_middleware` | 请求日志、`X-Trace-Id` |

后注册的在外层。trace 在外层，所以**被限流拦掉的 429 也会被记录**。

**② `backend/app/core/config.py`（54 行）**

所有配置项集中在这，`.env` 覆盖默认值。`TRUSTED_PROXIES` 是部署相关，读第 156 行附近的注释。

**③ `backend/app/api/v1/__init__.py`**

18 个路由模块怎么拼起来的。前缀 `/api/v1` 就是这里加的。

### 阶段 B：跟一条完整链路（30 分钟）★ 最有效

挑**登录**这条最简单的链路，从接口一路读到数据库：

```
POST /api/v1/auth/login
  └─ api/v1/auth.py        login()        取参数、调 service
      └─ services/auth_service.py  login()  查用户、验密码、签发 JWT
          └─ core/security.py     PBKDF2 校验
              └─ core/deps.py     _load_user()  之后每次请求靠它认人
```

读完这条，你已经知道：**接口怎么定义、业务在哪写、密码怎么存、token 怎么发**。

### 阶段 C：看四个核心机制（45 分钟）

| # | 文件 | 关键位置 | 看什么 |
|---|---|---|---|
| 1 | `app/core/deps.py` | 第 11 行 `_load_user`、第 45 行 `require_role` | JWT 解析、角色校验的闭包写法 |
| 2 | `app/models/book.py` | 第 68 行 `is_online` | **hybrid 属性**：一个判断同时能用在 Python 和 SQL 里 |
| 3 | `app/services/chapter_service.py` | 第 79 行 `watermark.embed` | 付费拦截 + 零宽水印 |
| 4 | `app/core/ratelimit.py` | 第 24 行 `RULES`、第 156 行 `client_ip` | 令牌桶、UA 拦截、可信代理 |

**关于 `is_online`（很容易看漏但很重要）**

```python
@hybrid_property
def is_online(self): ...          # Python 里用：if book.is_online
@is_online.expression
def is_online(cls): ...           # SQL 里用：where(Book.is_online)
```

同一个名字，两种用法。好处是「前台可见」的定义只有一处，
不会出现改了 A 处忘了 B 处。

### 阶段 D：其余功能按需看（30 分钟）

| 想看什么 | 去哪个文件 |
|---|---|

| 敏感词过滤 | `app/services/moderation_service.py` |
| 评论 / 间贴 | `app/services/comment_service.py`、`interaction_service.py` |
| 钱包、签到、充值 | `app/services/wallet_service.py` |

## 4. 前端阅读路线（1 小时）

### 阶段 A：启动与路由（15 分钟）

| `src/App.vue` | 根组件，`<router-view>` 在这 |

### 阶段 B：数据怎么来（10 分钟）

`src/api/request.js`（34 行）：

```js
service.interceptors.request.use(...)   // 第 7 行：每个请求自动带 token
service.interceptors.response.use(...)  // 统一取 res.data.data、统一弹错误
```

所以页面里写 `const data = await getBooks(...)`，拿到的**直接是 `data`**，
不用再 `.data.data`。

`src/api/index.js` 是接口清单，页面按需 import。

### 阶段 C：读三个典型页面（35 分钟）

| 页面 | 难度 | 看什么 |

## 5. 跟着一个功能走完前后端

以「给某一段发间贴」为例，这是最能体现整体设计的一条链路：

| 层 | 文件 | 做什么 |
|---|---|---|
| 1. 页面 | `frontend/src/views/Reader.vue` | 点段落右侧「+」→ 收集内容 → `addParagraphComment()` |
| 2. 接口封装 | `frontend/src/api/index.js`（`addParagraphComment`） | `POST /paragraph-comments` |
| 3. 后端路由 | `backend/app/api/v1/interaction.py` | 校验入参（`ParagraphIn`）→ 调 service |
| 4. 敏感词 | `backend/app/services/moderation_service.py` | `enforce()`：命中 block 直接抛 5001 |
| 5. 业务 | `backend/app/services/interaction_service.py` | 写入 `paragraph_comment`，按是否命中 review 词决定 `audit_status` |
| 6. 持久化 | `backend/app/models/paragraph_comment.py` | 表结构 |
| 7. 返回 | — | `ok({...})` → 前端刷新列表 |

途中任何一个环节出错，都会返回统一结构 `{code, message, data, trace_id}`，
前端拦截器按 `code != 0` 弹出 `message`。

## 6. 读代码时容易卡住的几个点

| 困惑 | 解释 |
|---|---|
| 为什么 `service` 里到处 `from app.services import xxx` 写在函数内部？ | 避免循环导入。模块顶层互相 import 会报 `ImportError` |
| 为什么有的查询要用 `db.flush()`？ | 会话配置了 `autoflush=False`（`core/database.py` 第 21 行），聚合查询看不到未提交的改动 |
| `Book.is_online` 为什么能出现在 `where()` 里？ | SQLAlchemy 的 `hybrid_property` + `.expression`，同时支持对象与 SQL 两种用法 |
| 路由函数为什么有时返回 `dict` 有时返回 `Response`？ | 正常走 `ok(dict)` 由 FastAPI 序列化；需要设响应头时（付费章节 `no-store`）直接返回 `Response` |
| 前端 `api` 目录怎么分工？ | `src/api/index.js` 是「读者端 + 通用」接口汇总；`admin.js` / `author.js` / `wallet.js` 按端拆分；`request.js` 是 axios 实例 |
| 为什么 `main.py` 的中间件顺序和我预期相反？ | Starlette 中**后注册的在外层**，请求先经过后注册的 |

## 7. 调试手段

| 想看什么 | 怎么做 |
|---|---|
| 某个接口收什么参数 | 打开 <http://127.0.0.1:8000/docs>，可直接在线调用 |

| 断点调试 | PyCharm 里对 `main.py` 右键 `Debug 'main'`，就能在 service 打断点 |

| 前端请求报错 | 浏览器 F12 → Network → 看 response 的 `code` 与 `message` |

## 8. 三个练手任务（读完可以试着改）

由易到难，改完都能立刻看到效果：

1. **加一个敏感词**
   后台 → 敏感词库 → 新增「测试词」→ 去间贴里发一句含这个词的话。

2. **改限流阈值**
   `backend/app/core/ratelimit.py` 第 24 行 `RULES`，把 `auth` 从 6 改成 20，
   重启后端，再连续登录错误试试——第 21 次才 429。

3. **给书籍详情加一个字段**
   `models/book.py` 加列 → `schemas/book.py` 加字段 → `services/book_service.py` 的
   `to_card()` 里赋值 → 前端 `BookDetail.vue` 显示。走完这一遍就理解了整条数据流。
