# 01 · 需求规格说明书

> 系统名称：基于 Python 的轻量化 Web 小说平台
> 版本：v1.0　编写日期：2026-11-26
> 用途：开题报告 / 论文第 2 章「需求分析」的直接素材

---

## 1. 项目背景与目标

### 1.1 背景

网络文学阅读是典型的高频、轻量、强留存场景：用户单次停留时间短、翻页频繁、对首屏速度敏感；同时平台侧需要管理海量书籍与章节、维护分类与榜单、承载用户的书架与评论。

现有商业平台（起点、刺猬猫、纵横等）功能庞杂，包含付费、月票、作家签约、社区等运营体系。本项目**剥离商业运营部分，保留"找书—看书—追书"的核心阅读闭环**，实现一个功能完整、结构清晰、可独立部署的 Web 小说阅读平台。

### 1.2 建设目标

| 编号 | 目标 | 衡量标准 |
|---|---|---|
| G1 | 实现完整的阅读闭环 | 用户可在 3 次点击内从首页到达正文 |
| G2 | 实现内容管理闭环 | 管理员可完成「建分类 → 上架书 → 发布章节 → 审核评论」全流程 |
| G3 | 前后端彻底分离 | 前端仅通过 HTTP JSON 与后端通信，可独立部署 |
| G4 | 工程规范可追溯 | 有设计文档、接口契约、开发日志、运行日志 |

### 2.2 结论

商业平台的复杂度主要来自**商业化**（付费、分成、运营活动）和**社区化**（论坛、书友圈），而非阅读本身。
本项目的功能边界应当是：**把「找书—看书—追书」做到体验完整，其余一律砍掉。**

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 标识 | 说明 |
|---|---|---|
| 游客 | `anonymous` | 未登录用户，可浏览与阅读免费章节 |
| 读者 | `reader` | 注册用户，可有书架、进度、评论 |
| 作者 | `author` | 在读者权限基础上，可管理自己的作品与章节（P3） |
| 管理员 | `admin` | 内容审核、用户管理、分类维护、数据统计 |

> 角色为**单值枚举**（`sys_user.role`），不做多角色叠加。作者同时具备读者能力，管理员同时具备作者能力，通过「权限继承」实现，避免角色-权限表带来的复杂度。

## 4. 功能需求

> 优先级：**P0** = 必须（否则系统不成立）；**P1** = 应该（完整度）；**P2** = 可选（加分）。
> 编号规则 `FR-模块-序号`，后续接口文档、测试用例、论文均引用此编号。

### FR-01 用户模块

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-01-01 | 用户注册 | 用户名 + 密码 + 可选邮箱；用户名唯一，长度 3~20，密码 6~32，需二次确认 | P0 |
| FR-01-02 | 用户登录 | 用户名 + 密码，返回 JWT，有效期 2 小时 | P0 |
| FR-01-03 | 获取当前用户 | 凭 Token 拉取当前登录用户信息 | P0 |
| FR-01-04 | 退出登录 | 前端清除 Token（后端无状态，可选黑名单） | P0 |
| FR-01-05 | 修改资料 | 昵称、头像、个人简介 | P1 |
| FR-01-06 | 修改密码 | 校验旧密码 | P1 |
| FR-01-07 | 账号禁用 | 管理员可禁用/解禁账号，禁用后不可登录 | P1 |

**业务规则**
- BR-01：密码以 PBKDF2-HMAC-SHA256（迭代 26 万次）哈希存储，禁止明文或可逆加密。格式 `pbkdf2_sha256$iter$salt$hash`。
- BR-02：用户名不区分大小写唯一（建库时使用 `utf8mb4_0900_ai_ci` 排序规则天然满足）。
- BR-03：登录失败统一提示「用户名或密码错误」，不暴露账号是否存在。

### FR-02 书籍浏览

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-02-01 | 首页聚合 | 轮播推荐、分类入口、榜单 Top10、最近更新、精选书籍 | P0 |
| FR-02-02 | 分类列表 | 按一级分类查询书籍 | P0 |
| FR-02-03 | 书库筛选 | 分类 × 状态（连载/完结）× 排序（最新/最热/字数） | P1 |
| FR-02-04 | 书籍详情 | 封面、书名、作者、分类、标签、字数、状态、简介、最新章节、目录入口、书评区 | P0 |
| FR-02-05 | 章节目录 | 分页展示全部章节，标识最新章 | P0 |
| FR-02-06 | 最近更新列表 | 全站按 `last_update_at` 倒序 | P0 |
| FR-02-07 | 排行榜 | 点击榜 / 收藏榜 / 推荐榜 / 新书榜，各 Top N | P1 |

**业务规则**
- BR-04：仅 `audit_status = 1`（审核通过）且 `status != 2`（未下架）的书籍对外可见。
- BR-05：书籍列表不返回完整简介以外的重字段，避免列表接口过重。

### FR-03 阅读

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-03-01 | 章节正文 | 返回标题、正文、所属书籍、上一章/下一章 ID | P0 |
| FR-03-02 | 翻页 | 上一章 / 下一章 / 返回目录 | P0 |
| FR-03-03 | 阅读设置 | 字号（小/中/大/特大）、背景（白/米黄/护眼绿/夜间）、行距 | P1 |
| FR-03-04 | 设置持久化 | 存 `localStorage`，换页不重置 | P1 |
| FR-03-05 | 进度自动上报 | 进入章节 3 秒后上报一次，避免误触 | P1 |
| FR-03-06 | 快捷键 | ← → 翻章，Esc 返回目录 | P2 |

**业务规则**
- BR-06：正文以**纯文本 + `\n` 分段**存储，前端按行渲染为 `<p>`，禁止直接 `v-html` 渲染用户/作者输入的 HTML（防 XSS）。
- BR-07：章节不存在或已删除时，提示并可返回书籍详情页。

### FR-04 书架与阅读进度

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-04-01 | 加入书架 | 同一本书不可重复收藏 | P0 |
| FR-04-02 | 移出书架 | — | P0 |
| FR-04-03 | 书架列表 | 展示封面、书名、最新章、**读到第几章**、更新时间 | P0 |
| FR-04-04 | 书架置顶 | 置顶显示，最多 3 本 | P2 |
| FR-04-05 | 继续阅读 | 一键跳转到上次阅读章节 | P0 |
| FR-04-06 | 最近阅读 | 不在书架中但读过的书，单独展示 | P1 |
| FR-04-07 | 更新提醒 | 书架内书籍有更新时显示红点/角标 | P2 |

### FR-05 评论（书评 / 章评）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-05-01 | 发表书评 | 书籍详情页，绑定 `book_id` | P0 |
| FR-05-02 | 发表章评 | 阅读页，绑定 `book_id + chapter_id` | P1 |
| FR-05-03 | 回复评论 | 一级回复（`parent_id`），不做无限嵌套 | P1 |
| FR-05-04 | 评论列表 | 按时间倒序，分页 | P0 |
| FR-05-05 | 删除自己的评论 | 逻辑删除（`status = 2`） | P1 |
| FR-05-06 | 点赞 | 评论点赞数 +1（可选做去重） | P2 |
| FR-05-07 | 评论审核 | 管理员可将评论置为「待审/隐藏」 | P1 |

**业务规则**
- BR-08：评论长度 1~500 字，需过滤纯空白。
- BR-09：不做敏感词库（成本高收益低），改为**发布即显示 + 管理员事后审核**，论文中说明为「先发后审」策略。

### FR-06 作者中心（P3，可选）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-06-01 | 申请成为作者 | 管理员审核或自助升级 | P2 |
| FR-06-02 | 我的作品列表 | 仅可见自己的书 | P2 |
| FR-06-03 | 创建作品 | 书名、分类、简介、封面 | P2 |
| FR-06-04 | 编辑作品 | 修改简介、状态（连载/完结） | P2 |
| FR-06-05 | 发布章节 | 章节号自动递增、标题、正文 | P2 |
| FR-06-06 | 编辑/删除章节 | 仅自己的作品 | P2 |

**业务规则**
- BR-10：发布章节后自动回写 `book.word_count`、`book.chapter_count`、`book.last_chapter_id`、`book.last_update_at`（在同一事务内完成）。

### FR-07 管理后台

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-07-01 | 数据看板 | 用户数、书籍数、章节数、评论数、今日新增 | P1 |
| FR-07-02 | 书籍管理 | 增删改查、上架/下架、推荐位设置 | P0 |
| FR-07-03 | 章节管理 | 按书籍查看章节，批量导入（粘贴文本自动分章） | P1 |
| FR-07-04 | 分类管理 | 增删改、排序 | P1 |
| FR-07-05 | 用户管理 | 列表、搜索、禁用/解禁、改角色 | P1 |
| FR-07-06 | 评论管理 | 列表、按书籍筛选、隐藏/删除 | P1 |
| FR-07-07 | 标签管理 | 增删 | P2 |

> **批量导入**是效率关键：管理员粘贴一整段「第1章 xxx\n正文……\n第2章 xxx\n正文……」，系统按正则自动切分入库。没有这个功能，录入 20 本书会累死。

### FR-08 搜索

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| FR-08-01 | 关键词搜索 | 匹配书名、作者名 | P0 |
| FR-08-02 | 高亮 | 前端高亮命中词 | P2 |
| FR-08-03 | 搜索建议 | 输入时下拉提示书名 | P2 |

**实现说明**：P1 阶段使用 `LIKE '%kw%'`；P4 阶段升级为 MySQL `FULLTEXT` + `ngram` 分词器，论文中作为「查询优化」对比实验。

## 5. 用例规约

> 共 15 个核心用例。论文「用例图」可按角色分三簇：读者（UC-01~13）、作者（UC-14）、管理员（UC-15）。
> 完整规约的格式：**前置条件 → 主流程 → 异常流 → 后置条件**。

### UC-01 用户注册

| 项 | 内容 |
|---|---|
| 参与者 | 游客 |
| 前置 | 未登录 |
| 主流程 | ① 点击「注册」→ ② 输入用户名、密码、确认密码 → ③ 前端校验格式 → ④ 提交 → ⑤ 后端校验用户名未占用 → ⑥ bcrypt 加密入库 → ⑦ 自动登录并跳转首页 |
| 异常流 | ③ 格式不符：就地提示；⑤ 用户名已存在：返回 `2001`；两次密码不一致：前端拦截 |
| 后置 | `sys_user` 新增一条 `role = reader` 记录 |

### UC-02 用户登录

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 任意角色 |
| 前置 | 已注册且未被禁用 |
| 主流程 | ① 输入用户名密码 → ② 提交 → ③ 后端查用户 → ④ bcrypt 校验 → ⑤ 检查 `status = 1` → ⑥ 签发 JWT（含 `sub`、`role`、`exp`）→ ⑦ 前端存 Token 与用户信息 → ⑧ 跳转来源页或首页 |
| 异常流 | 用户不存在或密码错：统一返回 `2002`；账号禁用：返回 `2003`；Token 过期：后续请求返回 `1002`，前端跳登录 |
| 后置 | 更新 `last_login_at` |

### UC-03 浏览首页

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 读者 |
| 主流程 | ① 打开首页 → ② 并行请求「轮播推荐 / 分类 / 四类榜单 / 最近更新」→ ③ 渲染各区块 → ④ 点击任意书籍卡片进入详情 |
| 性能要求 | 首页首屏 ≤ 2s（本地环境），接口聚合为 ≤ 4 个请求 |
| 异常流 | 某区块接口失败时局部降级显示「暂无数据」，不阻塞整页 |

### UC-04 按分类筛选书籍

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 读者 |
| 主流程 | ① 顶部导航点击分类 → ② 进入书库页（带 `category_id`）→ ③ 展示列表（分页 20/页）→ ④ 可叠加筛选：状态、排序 → ⑤ 点击书籍进入详情 |
| 异常流 | 分类不存在：展示空态并提供返回首页 |

### UC-05 搜索书籍

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 读者 |
| 主流程 | ① 顶部搜索框输入关键词回车 → ② 跳转搜索结果页 `?keyword=` → ③ 后端按书名/作者模糊匹配 → ④ 展示结果与总数 |
| 异常流 | 关键词为空：不发起请求；无结果：显示空态 + 推荐热门书 |

### UC-06 查看书籍详情

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 读者 |
| 前置 | 书籍存在且已上架 |
| 主流程 | ① 进入详情页 → ② 请求书籍基本信息 + 最新章节 + 前 N 章目录 + 书评首页 → ③ 展示封面/简介/标签/字数/状态 → ④ 提供「开始阅读」「加入书架」「查看全部目录」入口 |
| 异常流 | 书籍不存在或已下架：404 页面 |
| 后置 | `book.click_count` 自增（异步或延迟，避免阻塞） |

### UC-07 阅读章节

| 项 | 内容 |
|---|---|
| 参与者 | 游客 / 读者 |
| 前置 | 章节存在 |
| 主流程 | ① 点击章节 → ② 请求章节内容（含 `prev_id`/`next_id`）→ ③ 渲染标题与正文 → ④ 显示顶部/底部翻页条 → ⑤ 应用本地阅读设置（字号/背景）→ ⑥ 若已登录，3 秒后上报阅读进度 |
| 异常流 | 章节被删除：提示并提供返回目录 |
| 后置 | `reading_history` Upsert 一条 `(user_id, book_id)` 记录 |

### UC-08 加入书架

| 项 | 内容 |
|---|---|
| 参与者 | 读者 |
| 前置 | 已登录，书籍存在 |
| 主流程 | ① 详情页点击「加入书架」→ ② 未登录先跳登录 → ③ 后端检查是否已收藏 → ④ 插入 `user_bookshelf` → ⑤ 按钮变为「已在书架」，`collect_count` 自增 |
| 异常流 | 重复收藏：返回 `4001`，前端幂等处理为「已在书架」 |

### UC-09 管理书架

| 项 | 内容 |
|---|---|
| 参与者 | 读者 |
| 主流程 | ① 进入书架页 → ② 展示收藏书籍（含读到第几章）→ ③ 可「继续阅读」/「移出书架」/「置顶」 |
| 异常流 | 空书架：引导去书库逛逛 |

### UC-10 记录与恢复阅读进度

| 项 | 内容 |
|---|---|
| 参与者 | 读者 |
| 主流程 | ① 阅读页停留 3s → ② 上报 `book_id + chapter_id + progress` → ③ 后端按 `(user_id, book_id)` Upsert → ④ 下次进入详情/书架时显示「继续阅读：第 N 章」 |

## 7. 验收标准（答辩自检清单）

系统须能现场完成以下 10 个动作，且无报错：

1. 用管理员账号登录后台，新建一个分类「科幻」。
2. 后台新增一本书，填书名、简介、上传封面、选分类。
3. 粘贴 3 章正文，使用「自动分章」导入。
4. 前台首页能看到这本书出现在「最近更新」。
5. 注册一个新读者账号，登录。
6. 搜索书名能找到该书，进入详情页看到 3 章目录。
7. 阅读第 1 章，字号调大、切换夜间模式，翻到第 2 章。
8. 返回详情页，显示「继续阅读：第 2 章」。
9. 加入书架，书架页显示该书与进度。
10. 发表一条书评，后台评论管理中可见并可隐藏。

## 8. 范围外说明（写入论文「局限与展望」）

| 不做的事 | 原因 |
|---|---|
| 付费订阅与结算 | 涉及资金合规、对账、退款，超出本科毕设合理范围 |
| 真实并发压测与分布式部署 | 单机部署即可满足演示，分布式属于过度设计 |
| 内容安全审核（敏感词/AI 审核） | 需第三方服务或词库，采用「先发后审」替代 |
| 移动端原生 App | 响应式 Web 已覆盖移动浏览场景 |
| 多语言 | 目标用户为中文读者 |
